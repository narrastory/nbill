# 前端对接变更说明

本文档面向已经使用过旧接口或旧统计口径的前端。新开发应直接以本目录其余文档为准。

## 当前契约基线

- 手册基线日期：2026-09-11。
- API 根路径：`/api`。
- 数据表结构未改变；保留现有字段名和大小写。
- 监听地址仍为 `0.0.0.0`，本机默认端口为 `9081`。
- 接口数据来自本地单用户账本，登录后加载到当前服务会话。

## 统计口径已明确

- 普通收支：`Income - Expense = netIncome`。
- 外部往来现金流：`In - Out = netCashFlow`。
- 现金变化：普通净收入加外部净现金流。
- 期末现金：期初现金加期间现金变化。
- 未结清额按关联业务组计算，不再把单条 `Out` 直接当作最终欠款。
- 指定开始日期时，summary 使用紧邻且等长的上一周期比较。
- 比较基数为零时返回 `null`，前端不得当作 0%。
- 所有日期区间均为闭区间。

详细公式见 [BUSINESS_RULES.md](./BUSINESS_RULES.md)。

## 分析接口分层

- `/analytics/summary`：首页轻量统计，包含现金、普通收支、外部往来、环比和支出分类排行。
- `/analytics/external-outstanding`：未结清、已结清、超额流入、无匹配流入的业务组分析。
- `/analytics/data-quality`：字段、字典引用、关联 ID 等完整性检查。
- `/analytics`：完整分析页使用，包含趋势、分位数、分布、帕累托、标签、异常和年度大额记录。

旧前端若只调用完整 `/analytics` 渲染首页，建议改为 summary，以减少不必要计算和传输。

## 前端必须注意的兼容点

- `Flowtype` 的 `t` 小写，`Relatedparty` 的 `p` 小写；不要擅自改成 `FlowType` 或 `RelatedParty` 后直接提交。
- 普通流水日期是 `BillDate`；外部往来日期是 `FlowDate`。
- 外部往来列表不展开 `relatedTransactions`，详情接口才展开。
- 编辑接口不允许改变原始日期。
- 超过编辑窗口的 PUT 需要用户确认后追加 `confirmHistoricalEdit=true`；DELETE 无绕过机制。
- 字典只支持新增和重命名，不支持删除。重命名会级联更新已有引用。
- `data-quality` 发现问题仍返回 HTTP 200，必须检查 `healthy`。
- 完整 analytics 实时计算；写入后应清除前端分析缓存。

## 建议迁移步骤

1. 统一 API 客户端的 `401` 处理和错误结构。
2. 按 [DATA_SCHEMA.md](./DATA_SCHEMA.md) 校正字段大小写与 nullable 类型。
3. 把首页统计切换到 `/analytics/summary`。
4. 为历史 PUT 增加二次确认重试。
5. 外部往来增加“流水列表”和“未结清业务组”两个视角。
6. 检查所有百分比组件能正确显示 `null`。
7. 按 [FRONTEND_GUIDE.md](./FRONTEND_GUIDE.md#联调验收清单) 完成联调。

## 安全与隐私

本项目只在本地部署，因此没有引入面向公网系统的复杂权限体系。前端仍应做到：不硬编码密码、不在日志打印凭据、不把 token 放进 URL、遇到 401 清理会话。这些措施实现成本低，也能避免本机日志、浏览器历史和代码仓库意外泄露凭据。
